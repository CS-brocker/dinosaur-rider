# 12장 I/O

## 1. 개요

컴퓨터에는 키보드, 디스크, 네트워크 카드처럼 동작 방식이 서로 다른 장치가 많다.

운영체제의 I/O 시스템은 이러한 차이를 숨기고, 프로그램이 `read()`, `write()` 같은 **일관된 인터페이스**로 장치를 사용할 수 있게 한다.

- 장치별 차이는 **장치 드라이버**가 처리한다.
- 운영체제는 모든 장치에 공통된 **추상화와 서비스**를 제공한다.

---

## 2. I/O 하드웨어

### 장치와 호스트의 연결

포트, 버스, 장치 컨트롤러를 통해 CPU·메모리와 연결된다.

- **포트(port)**: 장치와 컴퓨터가 연결되는 지점
- **버스(bus)**: 여러 장치가 공유하는 통신 경로
- **장치 컨트롤러(device controller)**: 장치를 직접 제어하는 하드웨어
- **장치 드라이버(device driver)**: 컨트롤러를 다루는 운영체제 소프트웨어

<컨트롤러의 레지스터>

- **데이터 레지스터**: 전송할 데이터
- **상태 레지스터**: 장치가 준비되었는지, 오류가 발생했는지 표시
- **제어 레지스터**: 읽기·쓰기 같은 명령 전달

### Memory-Mapped I/O

\: 장치 레지스터를 메모리 주소 공간의 일부로 배치하는 방식

- CPU가 일반적인 메모리 접근 명령으로 장치 레지스터에 접근할 수 있어 별도의 I/O 명령이 필요하지 않다.

---

## 3. I/O 제어 방식

### 폴링(Polling)

\: CPU가 장치의 상태 레지스터를 반복해서 확인한다.

- 구현이 단순하다.
- 장치가 준비될 때까지 CPU 시간을 낭비하는 **바쁜 대기**가 발생한다.
- 매우 빠른 장치이거나 대기 시간이 짧으면 유용할 수 있다.

### 인터럽트 기반 I/O

\: CPU가 장치에 작업을 요청한 뒤 다른 작업을 수행한다. 장치가 작업을 완료하면 인터럽트를 발생시켜 CPU에 알린다.

```
CPU가 I/O 요청
 → CPU는 다른 작업 수행
 → 장치 작업 완료
 → 인터럽트 발생
 → 인터럽트 서비스 루틴 실행
```

- CPU 낭비를 줄일 수 있지만 인터럽트 처리와 문맥 저장·복원 비용이 발생한다.

### DMA(**Direct Memory Access)**

\: 장치 컨트롤러가 CPU를 거치지 않고 장치와 메모리 사이에서 데이터 블록을 직접 전송하는 방식이다.

<CPU가 DMA 컨트롤러에 전달하는 정보>

- 데이터가 위치할 메모리 주소
- 전송할 데이터 크기
- 전송 방향

→ 전송이 완료되면 DMA 컨트롤러가 CPU에 인터럽트를 보낸다.

| 방식 | CPU 역할 | 적합한 상황 |
| --- | --- | --- |
| 폴링 | 상태를 계속 확인 | 매우 짧거나 단순한 I/O |
| 인터럽트 | 완료 시점에만 처리 | 일반적인 I/O |
| DMA | 전송 설정과 완료 처리 | 대용량·고속 데이터 전송 |

## 4. 응용 프로그램 I/O 인터페이스

### 블록 장치

\: 데이터를 일정 크기의 블록 단위로 읽고 쓴다.

- HDD, SSD, 저장장치
- 임의 위치 접근이 가능하고 보통 버퍼링이나 캐싱이 사용된다.

### 문자 장치

\: 연속적인 바이트 스트림 형태로 데이터를 주고받는다.

- 키보드, 마우스, 직렬 포트
- 일반적으로 임의 위치 접근을 제공하지 않는다.

### 네트워크 장치

\: 일반적인 파일 입출력과 성격이 다르므로 주로 **소켓 인터페이스**를 사용한다.

### 클록과 타이머

\: 운영체제가 현재 시각 확인, 알람 설정, 프로세스 실행시간 제한 등에 사용한다.

---

## 5. 동기화 방식에 따른 I/O

### Blocking I/O

\: I/O가 끝날 때까지 호출한 프로세스가 대기한다. → 구현과 사용이 쉽지만 프로세스가 기다려야 한다.

### Nonblocking I/O

\: 요청을 즉시 처리할 수 없더라도 호출이 바로 반환된다. → 프로그램이 나중에 다시 상태를 확인해야 한다.

### Asynchronous I/O

\: I/O 요청만 제출한 뒤 프로그램은 다른 작업을 계속한다. → 작업이 완료되면 운영체제가 신호나 콜백 등으로 알려준다.

→ Nonblocking은 “지금 가능한 만큼 처리하고 즉시 반환”, Asynchronous는 “요청을 맡겨 두고 완료 통지를 받음”이라는 차이가 있다.

## 6. 커널 I/O 서브시스템

### I/O 스케줄링

\: 여러 I/O 요청의 처리 순서를 결정한다.

- 장치 이용률 향상
- 평균 응답시간 감소
- 프로세스 간 공정성 확보

### 버퍼링

\: 데이터를 전송하는 동안 임시 저장 공간인 **버퍼**에 보관한다.

<필요한 이유>

- 생산자와 소비자의 속도 차이 조절
- 장치와 프로그램의 전송 단위 차이 해결
- 비동기적인 데이터 생산과 소비 지원

### 캐싱

\: 자주 사용하는 데이터의 복사본을 빠른 저장장치에 보관한다.

- 버퍼의 주목적: 전송 중인 데이터의 임시 보관
- 캐시의 주목적: 같은 데이터에 대한 접근 속도 향상

→ 하나의 메모리 영역이 버퍼와 캐시 역할을 동시에 수행할 수도 있다.

### 스풀링

\: 동시에 여러 요청을 처리하기 어려운 장치를 위해 작업을 디스크 등에 모아 두었다가 순서대로 처리한다.

<예시: 프린터>

```
여러 프로세스의 출력 요청
        ↓
디스크의 프린트 큐
        ↓
프린터가 하나씩 출력
```

### 오류 처리

\: 장치 오류를 감지하고 응용 프로그램에 적절한 오류 코드로 전달한다.

### 보호

\: 일반 프로세스가 장치 컨트롤러를 직접 조작하면 시스템 전체에 영향을 줄 수 있다. 따라서 장치 제어 명령은 보통 특권 명령으로 제한하고 응용 프로그램은 시스템 호출을 통해서만 I/O를 요청한다.

## 7. I/O 요청이 하드웨어 작업으로 변환되는 과정

<프로그램이 파일을 읽는 과정>

1. 프로그램이 `read()` 시스템 호출을 실행한다.
2. 커널이 파일 디스크립터를 이용해 대상 파일과 장치를 찾는다.
3. 요청한 데이터가 캐시에 있는지 확인한다.
4. 캐시에 없으면 장치 드라이버를 호출한다.
5. 드라이버가 컨트롤러 레지스터에 명령을 기록한다.
6. 컨트롤러가 장치 작업 또는 DMA 전송을 수행한다.
7. 완료되면 인터럽트가 발생한다.
8. 인터럽트 처리기가 결과와 오류 여부를 확인한다.
9. 커널이 대기 중인 프로세스를 깨운다.
10. 데이터가 프로그램에 반환된다.

→ 시스템 호출 하나가 실제로는 여러 커널 계층과 하드웨어 단계를 거친다.

---

## 8. STREAMS

\: UNIX 계열 시스템에서 문자 기반 I/O와 네트워크 통신을 모듈식으로 구성하기 위한 구조

- 각 모듈은 읽기 큐와 쓰기 큐를 가지며, 필요에 따라 프로토콜 처리나 데이터 변환 기능을 추가할 수 있다.
- 장점: 기능을 모듈 단위로 조립할 수 있다.
- 단점: 여러 계층과 큐를 통과하면서 성능 비용이 발생할 수 있다.

---

## 9. I/O 성능

<시스템 성능의 주요 비용>

- 시스템 호출에 따른 사용자 모드와 커널 모드 전환
- 인터럽트 처리
- 프로세스 문맥 교환
- 여러 계층 사이의 데이터 복사
- 버퍼와 큐 관리
- 장치의 물리적인 지연

<개선 방법>

- DMA 사용
- 캐시와 버퍼 활용
- 불필요한 데이터 복사 제거
- 한 번에 더 큰 데이터 블록 전송
- 비동기 I/O 활용
- 인터럽트 병합
- 커널 계층과 문맥 전환 횟수 감소

→ 버퍼 크기를 무조건 키운다고 항상 빨라지는 것은 아니다. 메모리 사용량과 응답 지연도 함께 증가할 수 있다.
